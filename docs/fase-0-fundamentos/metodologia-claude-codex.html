El ciclo completo

flowchart TD
    A["Claude Code cierra un hito en main"] --> B["git push origin main"]
    B --> C["Codex: git fetch + checkout -B codex/<task> origin/main"]
    C --> D["Codex trabaja en su worktree y abre un PR"]
    D --> E{"Claude Code revisa el diff + corre los tests"}
    E -- cambios necesarios --> C
    E -- aprobado --> F["Merge a main + push"]
    F --> A

El punto de encuentro es siempre origin/main en GitHub — nunca el disco. Ninguno de los dos agentes "se entera" del otro en vivo; se entera la próxima vez que hace fetch.

Qué hacés vos, en cada punto

Cuando trabajás con Claude Code
  • Al cerrar un hito, confirmá que mergeé a main y pusheé a origin — si más tarde le vas a dar algo a Codex, necesita ver esto.
  • Si algo te suena a decisión de arquitectura en vez de tarea mecánica, decímelo — eso se queda acá, no se delega.
Cuando le delegás algo a Codex
  • Dale una tarea chica y ya acotada — nunca una decisión abierta.
  • Cuando abra un PR, no lo mergees vos — traémelo a Claude Code para revisión primero.
  • Si edité docs/DECISIONES.md recientemente, preguntame si eso ya está reflejado en AGENTS.md — son archivos distintos, y Codex solo lee el segundo.

Reglas de oro

  • 01Git es la única fuente de verdad. Nada está "sincronizado" solo porque el disco es el mismo, o porque alguien lo dijo en el chat.
  • 02Cada agente en su propia carpeta: ~/dev/AgentPay para vos y Claude Code, ~/dev/AgentPay-codex para Codex. Nunca se cruzan.
  • 03Ningún PR se mergea sin revisión — diff completo y tests corridos, con atención reforzada a cualquier cosa cerca de checkMandate o el enforcement de límites.
  • 04Toda sesión cierra con una entrada en docs/AGENT_LOG.md: rama, qué, por qué, qué falta. No es opcional.
Por qué las reglas son estrictas

El agente anterior en el rol de Codex (Devin) generó, en una rama que terminó borrada por completo, un adaptador que se saltaba checkMandate — un bypass de seguridad real, no hipotético (docs/fase-2-agente-compra/DECISIONES.md § B-25).

Y dos veces distintas —una con Devin, una con Codex— la carpeta compartida quedó parada en la rama equivocada al terminar una tarea. La regla de las carpetas separadas (P-5) existe porque la disciplina sola falló dos veces.
