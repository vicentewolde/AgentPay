## Un hallazgo que obligó a extender T6, no solo T8

Al construir el CLI apareció un hueco: `agentpass issue` firma y ancla una
credencial, pero anclar exige que el emisor esté **registrado y activo** en el
contrato. Nada en T6 ni T7 dejaba eso resuelto — el emisor se había registrado
a mano, con un script desechable, durante las pruebas de T7.

Eso rompía el criterio de aceptación: alguien clonando el repo por primera vez
habría llegado hasta `agentpass issue` y chocado con `IssuerNotRegistered`, sin
ningún comando documentado para resolverlo. `registerIssuer` es una operación
de administrador, deliberadamente fuera de la superficie de cuatro comandos del
CLI — así que la solución no era agregar un quinto comando, sino que
**`pnpm run deploy:registry` deje al emisor listo**, ya que es el único momento
en que el admin ya está en juego.

Verificado contra la red real, las dos ramas:

```

  ...
  issuer       GCTTRJIYYRHAOYTEG2YWKYSBKIQOMX7RX7SAJXQAM3QY2J7J453BOZD6 already registered and active
```

```

before: { registered: false, active: false }
```

(La segunda prueba usó una cuenta nueva generada solo para el test, a través de

## Un bug propio encontrado por los tests, no a mano

`revoke.ts` llamaba `Keypair.fromSecret(secret)` sin envolver el error, a
diferencia de `issue.ts`. El test
`rejects a malformed ISSUER_SECRET_KEY rather than an opaque crash` lo cazó de
inmediato: esperaba `ConfigError` y recibió el error crudo de la librería
Stellar. Se corrigió extrayendo `requireIssuerKeypair` a un módulo compartido
(`commands/shared.ts`) usado por ambos comandos, en vez de arreglarlo dos veces.
