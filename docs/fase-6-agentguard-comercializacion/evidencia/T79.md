## 1. La identidad de venue, ampliada (`C-87`)

Antes de proponer nada se verificó que el `contractId` de un venue **nunca se
usa para llamar a un contrato**:

```
$ grep -rn "parsed.contractId\|\.contractId" apps packages --include="*.ts" | grep -v test
apps/agent/src/payment/policy-rail-payer.ts   → el rail, no el venue
apps/agent/src/catalog/registry.ts:97         → makeVenueId(row.slug, row.contractId)
packages/mandate/src/anchor.ts                → el registry contract, no el venue
```

La única lectura del campo del venue lo pasa a `makeVenueId`. Es un
identificador que se compara byte a byte, no un ancla verificada.

## 3. Un defecto propio, encontrado por correr la prueba real

La primera corrida falló:

```
Error: invalid encoded string length: expected 56, got 58
    at Keypair.fromSecret (…/keypair.ts:131:30)
```

Causa: este repo guarda `.env.local` como `KEY="value"`, y el lector que
escribí para SignalDesk no quitaba las comillas — le pasaba una "semilla" de 58
caracteres a `Keypair.fromSecret`. **El servidor de SignalDesk tenía el mismo
bug**, así que habría fallado igual al arrancar contra un `.env.local` real.

Arreglado centralizando el lector en `apps/signaldesk/src/env.ts` (propio, no
importado de `scripts/lib`, porque el comercio no importa de la plataforma) y
con cuatro pruebas dedicadas, incluida la de las comillas.

Vale anotarlo: esto no lo encontró ningún test de los que escribí antes. Lo
encontró correr la cosa de verdad.

## 5. El guardarraíl que faltaba (`C-90`)

Al sumar la cuarta app se encontró que **`apps/status-dashboard` nunca estuvo
en las referencias del `tsconfig.json` raíz**, así que `pnpm typecheck` jamás
lo compiló:

```
$ npx tsc -p apps/status-dashboard/tsconfig.json --noEmit
status.ts(35,17):      error TS2304: Cannot find name 'VaultReaderFactory'.
server.ts(285,35):     error TS2345: ActivityDirectory is not assignable to SponsoredCreditDirectory.
status.test.ts(180,7): error TS2322: Type '"anchored"' is not assignable to '"derived" | "funded"'.
```

Ninguno rompía producción (el objeto real sí tiene `countFundedRails`), pero el
tipo mentía. Arreglado el guardarraíl primero y los errores después; al
compilarlo por primera vez aparecieron tres fixtures más con el mismo problema.
Ahora las cuatro apps están en las referencias del raíz.
