# T81 — evidencia

La lista blanca de URLs de retorno, y el cableado de RealOps con `/v1` hasta el
Mandato firmado. Rama `cc/t81-return-allowlist`.

---

## 1. La lista blanca, probada contra los ataques que existe para frenar

`packages/partner-api/src/return-urls.ts`, 13 pruebas. Las que importan:

```
✓ allows any path under a registered origin
✓ refuses a lookalike host, however it is dressed up
✓ refuses a URL that smuggles the allowed host into credentials
✓ treats a different scheme or port as a different origin
✓ refuses a scheme that is not a redirect at all
✓ refuses every URL for a partner that registered no origins
✓ keeps the four refusal reasons distinct
```

Los señuelos concretos que se rechazan, con `https://realops.example`
registrado:

| URL | Por qué la aceptaría una comparación ingenua |
|---|---|
| `https://realops.example.attacker.test/volver` | prefijo |
| `https://realops.example-attacker.test/volver` | prefijo |
| `https://attacker.test/realops.example` | "contiene" |
| `https://realops.example@attacker.test/volver` | credenciales: el origen real es `attacker.test` |
| `http://realops.example/volver` | esquema distinto |
| `https://realops.example:8443/volver` | puerto distinto |
| `javascript:alert(1)` / `data:text/html,…` | no es una redirección |

Y a nivel de ruta (`apps/web/src/partner-routes.test.ts`), cinco pruebas más:

```
✓ accepts a return_url whose origin the partner registered
✓ refuses an origin the partner never registered, without creating a session
✓ refuses a lookalike host
✓ refuses every return_url for a partner that registered none
✓ still creates a session with no return_url at all — the redirect is optional
```

La segunda cuenta las llamadas a `createConsentSession` y exige que **no haya
crecido**: se refuza antes de escribir, no después.

## 2. Lo que cambió en el esquema

Versión 8:

```sql
alter table directory_partners        add column if not exists return_origins text[] not null default '{}';
alter table directory_consent_sessions add column if not exists return_url text;
```

El `default '{}'` no es un relleno: **una lista vacía no permite nada**. En
concreto, todo partner que existía antes de T81 queda sin poder redirigir a
ningún lado hasta que alguien registre un origen a propósito — que es la
lectura fail-closed que `B-1` fijó para todas las listas de este sistema.

Registro con script de operador, que **reemplaza** en vez de agregar:

```bash
pnpm run partner:return-origins -- --partner ptn_… --origins https://agentpey-realops.onrender.com
```

## 3. El cliente `/v1` de RealOps, y dos errores por asumir rutas

`apps/realops/src/agentpey.ts` tiene **cuatro llamadas**, todas de pedir, y
ninguna clave capaz de otorgar nada.

La primera versión tenía dos errores que solo habrían aparecido contra el
servidor real, y que se encontraron **leyendo `partner-routes.ts`** en vez de
suponer:

1. Un camino de "ya existe → leer de vuelta" para el tenant. Innecesario:
   `POST /v1/tenants` ya responde `200` con el tenant existente cuando el mismo
   `external_ref` se afirma de nuevo (el comentario de la ruta lo dice: "la
   misma verdad afirmada dos veces no es un error").
2. `GET /v1/tenants/{id}/mandates`, que **no existe**. Los mandatos se listan
   con `GET /v1/mandates?tenant_id=`.

## 4. El flujo de firma, probado con un AgentPey falso

`apps/realops/src/signing.test.ts`, 9 pruebas:

```
starting a signature
  ✓ sends the person to AgentPey's consent page, not to one of ours
  ✓ identifies the person to AgentPey by the random reference, never by their email
  ✓ proposes exactly the grant the review screen showed
  ✓ asks to come back to its own origin, and keys the invitation to the agent
  ✓ refuses to start a signature for someone else's agent
coming back from signing
  ✓ believes AgentPey about what happened, not the browser
  ✓ shows the signed permission under Mis servicios
  ✓ 404s a return for an agent that never started signing
with no AgentPey configured
  ✓ says so instead of crashing
```

La tercera es la que fija `C-96`: toma el HTML que la persona **vio** en la
pantalla de revisión y exige que cada valor del grant **enviado** aparezca ahí.
Si alguien reconstruyera el grant del lado del cliente, esa prueba lo detecta.

La sexta prueba el retorno en dos tiempos: volviendo con la sesión todavía
`pending` no se guarda ningún mandato; recién cuando AgentPey dice `completed`
se guarda. El navegador no decide nada.

## 5. Un defecto encontrado por un test

`GET /agentes/{id}` matcheaba por prefijo (`startsWith`), así que se tragaba
`/agentes/{id}/volver` antes de que su handler existiera siquiera para verlo:

```
× coming back from signing > believes AgentPey about what happened, not the browser
  → expected 404 to be 302
```

Arreglado matcheando una forma de un solo segmento
(`/^\/agentes\/([^/]+)$/`), que no depende del orden en que estén escritos los
handlers — el arreglo por reordenar habría funcionado hasta que alguien moviera
un bloque.
