## El test de regresión de `C-17`, probado contra el bug real

Un test de regresión que no puede fallar no sirve de nada. Se reintrodujo
el bug exacto de `C-17` a propósito —la credencial nombrando a la
plataforma mientras el Mandato nombra a la wallet— y se corrió la suite:

```
 ✓ ... makes the credential's principal and the mandate's issuer the same party — classic path
 × ... makes the credential's principal and the mandate's issuer the same party — wallet path
 × ... names the connected wallet as that shared principal, not the platform
 ✓ ... falls back to the platform as principal when no wallet is connected
 × ... keeps the platform as the credential's issuer even when a wallet is the principal
 ✓ ... names the same agent in both documents
 ✓ ... gives both documents the same validity window
 ✓ ... grants exactly the credential's scope, not a narrower one
 ✓ ... points both documents at the same registry

      Tests  3 failed | 6 passed (9)
```

Nótese qué falla y qué no: el camino con wallet falla, el clásico pasa —
exactamente el patrón observado en producción, donde comprar sin wallet
funcionaba y con wallet no. Después se restauró el código correcto y los 9
volvieron a verde.

## Hallazgo: verde en `pnpm test` no quiere decir que compile

El primer intento de `session-documents.test.ts` pasó **9/9 en vitest con
los tipos rotos**: el fixture del scope usaba `{name, description, version}`
cuando `CredentialRequest` pide `{name, model, operator}`. `vitest` no
chequea tipos; lo agarró `pnpm typecheck`:

```
apps/web/src/session-documents.test.ts(28,5): error TS2322:
  Type '{ readonly agent: { readonly name: "demo"; readonly description: ...
  is missing the following properties from type '{ name: string; model: string; operator: string; }': model, operator
```

Vale para todo test que se escriba de acá en adelante, propio o delegado a
Codex: la suite en verde no reemplaza a `pnpm typecheck`.
