## 6. Verificación manual contra testnet real

Tres corridas con scripts descartables (nunca commiteados), usando
`ISSUER_SECRET_KEY` y `ADMIN_SECRET_KEY` —ambas ya fondeadas y ya
registradas— como dos wallets distintas, y `AGENT_SECRET_KEY` como la
cuenta pagadora compartida.

### 6.1 Primer intento — encontró un bug real, no simulado

```
[tenant1] session/start: 400 { pending: undefined, credentialHash: undefined, mandateHash: undefined }
```

Depurado con una llamada directa: el cuerpo completo del error era

```json
{
  "ok": false,
  "code": "SignerMismatch",
  "message": "the signing key is not the subject of the agent's own credential",
  "details": {
    "subject": "did:stellar:testnet:GAK6E5E7L63ZYFZZZFXDTYVG6MVAKILSHI5FITGH5U4ORACEZQ4GFP2K",
    "signer": "GAZIQAKOZFPQXFOAWUMKEDQOYFLREVYFB5H43BUJ5WMS5O4NDCKX6OVC"
  }
}
```

`subject` es la cuenta compartida (la credencial de este tenant, persistida
antes de T40, todavía la nombraba); `signer` es la identidad nueva recién
derivada para ese mismo tenant. Confirma `C-41`: la rehidratación de T39
comparaba credencial y mandato entre sí, nunca contra la identidad vigente.
Corregido agregando `currentAgentId` a `decideRehydration` — ver
`session-rehydration.ts` y sus dos tests nuevos.

```

  { "label": "entendido", "value": "1 x Swap Risk Quote (swap-risk-quote)" },
  { "label": "total", "value": "0.0010000 USDC" },
  { "label": "pagador", "value": "CCGAGRLV...4G3I (policy_rail, límites on-chain)" },
  { "label": "settled", "value": "true" },
  { "label": "tx", "value": "f4cbdee254d044aaea81e21bb150205e10440c9dc6410a0c53c42f4c5d51b12f" },
  { "label": "vault_anchor_hash", "value": "bf582241e5d533fd12af17b08d9a26049a942685b16de70ab8675a4403ad38b7" },
```

El `policy_rail` compartido (`CCGAGRLV...4G3I`) liquidó el pago aunque el
Mandato y la credencial de esta compra nombran a una identidad
completamente distinta como agente — confirma que la separación de `C-39`
funciona de punta a punta, no solo en la firma.

### 6.4 La identidad derivada sobrevive matar y levantar el proceso

Servidor detenido (`preview_stop`) y levantado de nuevo
(`preview_start`) — sin nada en memoria.

```
session/start after full process restart: 200 { pending: undefined,
  credentialHash: '4570d1d5...a82' }

✅ PASSED: tenant1's own derived identity survived a real process restart —
re-derived from (mnemonic, keyIndex), not cached anywhere.
```

Mismo hash de credencial exacto que antes del reinicio — la identidad no
vive en memoria en ningún lado: se recalcula desde `(MASTER_MNEMONIC,
key_index)` cada vez, y el `key_index` es lo único que persiste (en
Postgres, no secreto).
