### `POST /api/mcp` — probado dos veces, `500` las dos

```
$ curl -sS -X POST https://stellar-bazaar-x402.vercel.app/api/mcp \
    -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"list_services","arguments":{}}}'
# HTTP/2 500, content-length: 0, x-vercel-cache: MISS

$ curl -sS -X POST https://stellar-bazaar-x402.vercel.app/api/mcp \
    -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
    -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"agentpay-probe","version":"0.0.1"}}}'
# HTTP/2 500, content-length: 0, x-vercel-cache: MISS
```

Sin `Accept: text/event-stream` responde con un error JSON-RPC estándar
(`Not Acceptable`), así que el header estaba bien puesto — el `500` es del
servidor, en el primer paso del protocolo (`initialize`), no un método
específico.

### `GET /api/discovery/resources/{id}` — documentado, pero 404 real

```
$ curl -sS -D - https://stellar-bazaar-x402.vercel.app/api/discovery/resources/swap-risk-quote
HTTP/2 404
x-matched-path: /404
x-vercel-cache: HIT
content-type: text/html; charset=utf-8
<!DOCTYPE html>...<h1>Recurso no encontrado</h1><p>Este catálogo POC contiene sólo fixtures.</p>...
```

`x-vercel-cache: HIT` y `x-matched-path: /404`: es un 404 servido desde el
edge, no un error transitorio del backend. Confirma que la ruta no existe en
este despliegue pese a estar documentada en `/llms.txt`.

**Conclusión de esta sección:** `createBazaarCatalog` usa
`GET /api/discovery/search?query=*` como único transporte, y resuelve
`getProduct(id)` filtrando la lista completa en vez de golpear el endpoint de
recurso único. Ver `DECISIONES.md` → `B-25`.
