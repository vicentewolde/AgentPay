# SignalDesk

The pilot's merchant: an x402 service on Stellar testnet that sells two things,
takes USDC, and delivers only once the network has settled.

SignalDesk is **not part of AgentPey**. It holds its own Stellar keys, runs as
its own process, keeps its own tables, and imports nothing from the payment
platform beyond `@agentpass/core`'s neutral helpers. That separation is the
point: a merchant that could reach into AgentPey's authorisation would make the
whole demonstration circular.

## What it sells

| Product | Price | Delivery |
|---|---|---|
| `signaldesk:market-brief-xlm-usdc` | 0.25 USDC | A self-contained HTML brief on XLM/USDC |
| `signaldesk:ai-credits-1000` | 0.10 USDC | 1000 product credits, granted to one Stellar address |

The brief is **synthetic data generated by SignalDesk**, and says so in its
first line. It does not use, reproduce or imitate any real market data product.

The credits are an **entitlement, not an asset**: a row tied to one address,
with no transfer operation anywhere in this service. That is structural — a
transferable credit would be an issuance.

## Routes

| | |
|---|---|
| `GET /` | The human catalogue: prices, retention, and the key receipts verify against |
| `GET /api/discovery/search` | The `ServiceCard` feed an agent reads |
| `GET /api/x402/market-brief?pair=XLM/USDC` | Paid. `402` until a valid payment settles |
| `GET /api/x402/ai-credits?account=G…` | Paid. `402` until a valid payment settles |
| `GET /deliveries/{id}` | The artefact, as delivered |
| `GET /deliveries/{id}/receipt` | Its signed receipt |
| `GET /api/credits?account=G…` | A balance. Read-only — there is no route that moves one |

## Receipts

Every delivery produces a receipt naming the delivery, the product, the buyer,
the settled terms, the Stellar transaction, and the **hash of the exact bytes
delivered**. The receipt is canonicalised, hashed, and the hash is signed with
SignalDesk's key.

Anyone holding SignalDesk's public key can fetch the artefact, hash it, rebuild
the receipt and check the signature — with no AgentPey service and no trust in
this repository involved. That is what makes it evidence rather than a claim.
`verifyReceipt` in `src/receipts.ts` is that check, and it uses nothing from
AgentPey.

Artefacts are kept 90 days. After that the receipt and its hash remain, not the
file.

## Running it

One-time setup — mints SignalDesk's keys into `.env.local`, funds them on
testnet, opens its USDC trustline, and prints its `venues.json` row:

```bash
pnpm run signaldesk:setup
```

Start it:

```bash
pnpm run signaldesk
```

Buy from it for real on testnet, then verify the receipt the way a stranger
would (needs a payer holding testnet USDC in `AGENT_SECRET_KEY`):

```bash
pnpm run signaldesk:smoke
```

Tests, none of which touch the network:

```bash
pnpm --filter @agentpey/signaldesk test
```

## Storage

`signaldesk_deliveries` and `signaldesk_credits`, created on first use. With no
`DATABASE_URL` it runs on an in-memory store and loses everything on restart,
which is fine for a local look and wrong for anything else.

Deliveries are keyed on the settled payment transaction, so a retried request
returns the delivery already paid for instead of minting a second artefact.
